## [CRITICAL]

### C1. Дашборд молча рисует «нет данных» при 401 и при любой сетевой ошибке
`hr-dashboard/index.html:168-172` (`api()` — `r.json()` без проверки `r.ok`/статуса), `:174-191` (tickLive `catch {}`), `:193-223` (tickStatus `catch {}`), `:225-263` (tickChart `catch {}`).
- 401 отдаёт `{"error":...}` → `r.data` undefined → «—», «нет данных», «нет подключений», «за сутки пропусков нет ♥». Сетевой сбой → исключение проглатывается, интерфейс замирает на «—» / «загрузка...» / «обновление...» без единого сообщения.
- Фикс:
```js
async function api(path, params) {
  const url = BASE + path + (params ? '?' + new URLSearchParams(params) : '');
  const r = await fetch(url, { headers: { 'X-Api-Token': TOKEN } });
  const body = await r.json().catch(() => ({}));
  if (!r.ok) throw new Error('HTTP ' + r.status + (body.error ? ': ' + body.error : ''));
  return body;
}
```
и в каждом `catch (e)` показывать видимый баннер: `показатьError('Сервер недоступен/ключ не принят: ' + e.message)`, плюс всегда выводить время последнего УСПЕШНОГО обновления.

### C2. Автологин по сохранённому токену без проверки
`hr-dashboard/index.html:280` — `if (TOKEN) { showDash(); }` пускает на дашборд с любым (в т.ч. устаревшим) токеном; из-за C1 все запросы молча 401 → «пустой дашборд». `enterDash` (`:143-151`) проверяет токен только при ручном входе, сохранённый — никогда.
- Фикс: автологин через ту же валидацию: `api('/api/live')` → успех: `showDash()`; ошибка: показать gate с текстом «Ключ устарел или сервер недоступен: …».

### C3. Утечка медицинских данных: /journal и /raw/<device> без авторизации
`server/app.py:189-195` (journal), `server/app.py:216-220` (raw) — нет `check_api()`, в отличие от /series, /status, /gaps, /events, /api/*. Подтверждено: `curl /journal` без токена → 200 + весь ряд.
- Фикс: в оба обработчика первой строкой:
```python
err = check_api()
if err:
    return err
```

### C4. Quick-tunnel URL зашит в телефоне (MainActivity.DEFAULT_SERVER) — при смене туннеля телефон молчит вечно
`android/.../MainActivity.kt:40` (`DEFAULT_SERVER = "https://bargain-peter-birds-usual.trycloudflare.com"`), также `:259` — фоллбэк со СТАРЫМ мёртвым туннелем `formation-april-leads-diet`. trycloudflare-адрес меняется при каждом рестарте cloudflared. Телефон продолжает слать на старый адрес (Sender.kt: бэкофф 5 с → 5 мин, ошибка видна только мелким текстом в статусе). Именно так и выглядит текущее состояние (тишина с 14:13).
- Фикс: (а) постоянный адрес (named tunnel с собственным доменом) вместо quick tunnel; (б) в UI при `AUTH/FAILED`-состоянии > N минут — крупный красный статус «Адрес сервера устарел, обнови его в настройках»; (в) убрать фоллбэк с мёртвым URL.

## [HIGH]

### H1. Регенерация api_token.txt убивает все старые токены без предупреждения
`server/app.py:256-266` — если файла нет, молча создаётся новый токен. В сочетании с C1/C2: дашборд «перестаёт показываться» без объяснений. Доказательство из живой системы: файл создан сегодня 13:56.
- Фикс: не пересоздавать молча (логировать смену), + C1/C2 показывают причину. Опционально: `token` в конфиг/env, а не в файл рядом с БД.

### H2. События (причины разрывов) Android вообще не отправляет — требование «≥90% дыр объяснены» не работает
Сервер ждёт `events` в пачке (`app.py:96-99`) и `/events` (`:113-130`), но `Sender.kt:136-151` кладёт в payload только `device/sent_at/status/hr`; буфера событий нет нигде (LocalBuffer — только readings). В живой БД `events` = 0 строк → /gaps всегда «⚠ причина неизвестна».
- Фикс: в Android — таблица событий (bt_off, ble_lost, no_data, app_killed…) + отправка `events: [[ts,type,detail],…]` в каждой пачке (серверная часть уже готова).

### H3. События на сервере не идемпотентны — повторы пачки задваивают
`server/store.py:130-138` — обычный `INSERT` (в отличие от `insert_hr` c PK). Повтор /ingest или /events (обрыв после обработки, повтор Sender) дублирует события → задвоение explained_by и статистики.
- Фикс: `PRIMARY KEY (device, ts, type)` (или UNIQUE) + `INSERT OR IGNORE`, как в raw_hr.

### H4. Дубли пульса при повторе пачки с калибровкой часов
`server/app.py:75-84`: `offset = server_now - sent_at` считается ЗАНОВО на каждый запрос. Повтор той же пачки (телефон не получил ack) при |offset|>2 с сдвинет те же ts на другую величину → PK (device, ts) не сработает → задвоенный ряд.
- Фикс: хранить исходную метку: `ts_raw INTEGER` и PK (device, ts_raw); скорректированный ts — обычной колонкой/вычислением. Минимальный вариант — при вставке игнорировать строки, где у этого устройства уже есть ts в ±2 с.

### H5. Тесты нельзя запускать при живом сервере — они пишут в ПРОДОВУЮ БД
`server/simulator.py:11` — `BASE = "http://127.0.0.1:8091"` захардкожен, `test_sandbox.py:24,44` — порт 8091. Если 8091 занят продом: make_server падает «Address already in use», а при запуске на другом порту тестовые HTTP-запросы simulator ВСЁ РАВНО уходят в прод (порт в simulator не менялся) — fake-данные попадают в боевую БД. (Случилось в этом ревью — см. «Инцидент».)
- Фикс: параметризовать порт/URL (`sys.argv`/env `SBX_PORT`), использовать один источник BASE в обоих файлах; тестовую БД — во временный каталог.

### H6. Android: первый попавшийся источник пульса молча становится «выбранным»
`android/.../BleHrClient.kt:746-758` — при первом успешном потоке `prefs.preferredAddress = tgt.address`. Это противоречит собственному правилу из док-строки (:52-53: «к ДРУГИМ источникам не подключаемся — иначе можно записать пульс соседа»). Если первым подключился чужой датчик (соседский Polar — pickR берёт самый сильный RSSI с 0x180D), приёмник замыкается на него навсегда и пишет ЧУЖОЙ мед. пульс под видом Ники.
- Фикс: запоминать preferred только через `useDevice()` (явный выбор пользователя); в auto-режиме не сохранять.

## [MEDIUM]

### M4. Возраст данных и окно графика считаются по часам КЛИЕНТА

### M5. «Живой» пульс показывается безусловно, даже если ему сутки

## ТОП-3 причин пустого дашборда при «живом» сервере

1. **Просроченный токен + автологин без проверки + проглоченные ошибки (C1+C2+H1).** `api_token.txt` пересоздан сегодня в 13:56 → любой сохранённый раньше токен даёт 401 на каждом запросе, а дашборд молча рисует «— / нет данных / нет подключений». Выглядит ровно как «не показывает вообще». Проверка: «Сменить ключ / сервер» → ввести текущий токен заново; в Network вкладке DevTools будет 401.

2. **Телефон не доставляет данные (C4) — серверу нечего показывать.** Данные в БД кончились в 14:13:34 (за 47 с до перезапуска туннеля), alive=false. Пульс 87 на экране телефона — это локальный BLE-поток, он НЕ подтверждает связь с сервером (строка «Сервер: …» на экране приложения — вот индикатор). «Новый адрес» нужно вводить в ПРИЛОЖЕНИИ (скрытая секция «⚙ Сервер и ключ»), а не только в дашборде. При этом /api/live сейчас отдаёт устаревшее «133» — дашборд с верным токеном покажет «133, 25 мин назад», т.е. «почти пусто».

3. **BASE указывает на мёртвый/чужой туннель (C1-механика, L5).** Старый trycloudflare-URL в localStorage (или старое значение скрытого поля адреса) → fetch падает → `catch {}` → интерфейс замирает на «—»/«обновление...» без сообщения. Проверка: ввести адрес явно, убедиться https://, без слэшей на конце; баннер ошибки (после фикса C1) покажет точную причину.
